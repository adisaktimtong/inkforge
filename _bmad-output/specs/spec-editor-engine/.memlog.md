# Spec Memlog

- 2026-09-15 | topic | In-house, headless rich-text editor engine for React and Next.js CMS page content.
- 2026-09-15 | direction | Replace paid TinyMCE usage because product-specific customization has been difficult; flexibility is the primary driver rather than license cost alone.
- 2026-09-15 | decision | Existing CMS content remains HTML at the system boundary and is part of a page rather than an independently published article.
- 2026-09-15 | decision | The editor uses a structured document model internally and parses HTML on load and serializes HTML on save.
- 2026-09-15 | decision | The engine is headless and framework-independent; React and Next.js support is delivered through an adapter.
- 2026-09-15 | decision | Extensibility is plugin-first, covering nodes, marks, commands, keymaps, parsing, serialization, and UI composition.
- 2026-09-15 | constraint | Plugins dispatch commands and transactions and cannot mutate internal editor state directly.
- 2026-09-15 | constraint | The editor UI runs client-side in Next.js; saved, sanitized HTML can be rendered server-side without shipping the editor bundle.
- 2026-09-15 | constraint | Server-side HTML sanitization remains mandatory; the editor is not a security boundary.
- 2026-09-15 | capability | CAP-1: Import existing HTML into an editable structured document and export semantically equivalent HTML without losing supported content.
- 2026-09-15 | capability | CAP-2: Author the CMS MVP formatting set: paragraphs, headings, quotes, lists, inline marks, links, images, and code blocks.
- 2026-09-15 | capability | CAP-3: Extend content and behavior through plugins without modifying editor core.
- 2026-09-15 | capability | CAP-4: Integrate as a reusable form field in React applications while the parent form owns persistence.
- 2026-09-15 | capability | CAP-5: Operate in Next.js client boundaries while allowing server-rendered output HTML.
- 2026-09-15 | capability | CAP-6: Compose and theme toolbar UI independently from the headless engine.
- 2026-09-15 | capability | CAP-7: Preserve editing correctness across selection, keyboard commands, undo/redo, clipboard input, and IME composition including Thai text.
- 2026-09-15 | capability | CAP-8: Insert and edit images through an application-supplied upload integration with alt text support.
- 2026-09-15 | capability | CAP-9: Detect dirty state and expose deterministic HTML through change and imperative APIs for the containing page form.
- 2026-09-15 | non-goal | MVP does not target full TinyMCE feature parity, real-time collaboration, track changes, tables, video embeds, raw HTML source editing, or block drag-and-drop.
- 2026-09-15 | non-goal | Exact byte-for-byte preservation of arbitrary HTML, attribute ordering, and whitespace is not required; semantic preservation of the supported subset is required.
- 2026-09-15 | assumption | MVP is desktop-first and targets current evergreen browsers; the precise browser and mobile support matrix remains open.
- 2026-09-15 | assumption | Existing TinyMCE content primarily uses the MVP-supported HTML subset; production fixtures are needed to verify this.
- 2026-09-15 | question | Which browsers, minimum versions, and mobile editing environments are required?
- 2026-09-15 | question | How should unsupported legacy HTML be handled: unwrap, reject, or preserve as a sanitized read-only node?
- 2026-09-15 | question | Does existing content contain tables, media embeds, inline styles, or custom TinyMCE markup that must round-trip in MVP?
- 2026-09-15 | question | What image upload API and asset metadata contract must CAP-8 implement?
- 2026-09-15 | question | What accessibility conformance target is required?
- 2026-09-15 | event | Express distillation selected because the conversation supplies product intent, architecture direction, MVP boundaries, and output contract.
- 2026-09-15 | event | Coherence validation passed: every capability has an intent and demonstrable success criterion; constraints, non-goals, assumptions, and open questions are explicit.
- 2026-09-15 | event | Preservation validation passed: every load-bearing conversation decision is represented in SPEC.md, architecture.md, or html-contract.md; conversational wrapper content was intentionally omitted.
- 2026-09-15 | direction | ผู้ใช้กำหนดให้เอกสารสเปกและ companion ใช้ภาษาไทย โดยคงชื่อ API, type, code และ capability ID เป็นภาษาอังกฤษเพื่อใช้พัฒนาจริงได้ตรงกัน
- 2026-09-15 | event | การตรวจ coherence หลังแปลผ่าน: CAP-1 ถึง CAP-9 มีเจตนาและเกณฑ์สำเร็จครบ ข้อจำกัด สิ่งที่ไม่อยู่ในขอบเขต สมมติฐาน และคำถามเปิดยังคงชัดเจน
- 2026-09-15 | event | การตรวจ preservation หลังแปลผ่าน: ข้อกำหนด HTML, plugin-first architecture, React/Next.js boundary, Thai IME และ TinyMCE compatibility ยังคงอยู่ครบในเอกสารภาษาไทย

- 2026-09-15 | assumption | รายการ “กำหนดรูปแบบฟ้อน” ที่ปรากฏซ้ำหมายถึง font family use case เดียวกัน

- 2026-09-15 | event | การตรวจ preservation หลังเพิ่ม use case ผ่าน: color, highlight, block background, font size, font family, consumer menu และ modal action อยู่ครบใน SPEC.md, html-contract.md และ customization.md
- 2026-09-15 | decision | Typography, color, font และ background ใช้ design token ที่ consumer กำหนด ผู้เขียนไม่ป้อน CSS value อิสระ
- 2026-09-15 | decision | Responsive typography เก็บ semantic token ID ใน document model และให้ content CSS กำหนดค่าที่ต่างกันระหว่าง mobile/desktop รวมถึง line-height
- 2026-09-15 | decision | Presentation token serialize เป็น stable namespaced class เช่น `rte-typo-lead` แทน inline style หรือ `data-rte-typography`; class เหล่านี้เป็น public HTML contract และห้าม hash
- 2026-09-15 | decision | `data-*` ใช้เฉพาะ metadata เชิงโครงสร้างของ custom node ส่วน semantic meaning ใช้ HTML element และ presentation ใช้ token class
- 2026-09-15 | capability | CAP-5 ขยายให้ CMS preview และเว็บไซต์ใช้ versioned content stylesheet เดียวกัน โดยเว็บไซต์ไม่โหลด editor UI CSS หรือ editor runtime
- 2026-09-15 | capability | CAP-6 ขยายให้ custom modal action เก็บและคืน selection ก่อน dispatch command เพื่อให้คำสั่งทำงานกับตำแหน่งเดิม
- 2026-09-15 | constraint | CSS แยกเป็น editor UI stylesheet สำหรับ CMS และ content stylesheet สำหรับทั้ง CMS preview กับเว็บไซต์
- 2026-09-15 | constraint | เว็บไซต์ต้องรองรับ token class ใหม่ก่อน CMS เริ่มสร้าง HTML ที่ใช้ token นั้น และ token เดิมต้องมี alias/deprecation window จนเนื้อหาเก่าถูก migrate

- 2026-09-15 | constraint | Token ID ต้องเป็น safe slug และ content CSS ต้อง scope ใต้ `.rte-content` เพื่อป้องกัน class injection และ style leakage
